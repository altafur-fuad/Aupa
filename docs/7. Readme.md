# Food Delivery App — Engineering Docs

This folder contains the product and engineering plan for a food delivery platform built with **Flutter/Dart**, **Go**, **Rust**, and **Supabase PostgreSQL**, using a custom authentication service instead of Supabase Auth.

## Recommended architecture at a glance

- Flutter app calls **Go API over HTTPS**; no database secrets are shipped to the app.
- Go is the core backend for custom auth, REST APIs, order/payment orchestration and provider integrations.
- Rust is a narrowly scoped private dispatch/optimization worker, not a collection of premature microservices.
- Supabase PostgreSQL stores application data; schema changes are versioned SQL migrations.
- Direct Flutter-to-Supabase Data API access is disabled for the MVP. Custom JWT and Supabase `auth.uid()` semantics must not be conflated.

## Assumptions

- Bangladesh is the initial target market; timezone `Asia/Dhaka`, currency BDT.
- One customer order belongs to one restaurant.
- COD plus one online payment provider are the initial payment methods; provider selection is pending.
- The existing UI is a starting point. Integrate features into it rather than rebuilding visual screens without reviewing the current repo.
- Rust is used where a separate dispatch/optimization worker provides a defensible benefit. The system should launch with a minimal, tested worker rather than splitting every domain into a service.

## Document status

These documents are implementation-ready planning artifacts, not a statement that app code, payment accounts, production credentials, delivery operations or hosting have already been configured. Replace example hostnames/IDs/providers before launch. Any security-sensitive implementation requires code review and negative authorization tests.
