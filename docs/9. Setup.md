# Development Setup

This guide is a checklist. Exact versions should be pinned to the versions installed/selected by the project team; do not copy a random version number without compatibility testing.

## 1. Prerequisites

- Git, Flutter SDK + Dart (run `flutter doctor`), Android Studio/Android SDK and Xcode only if building iOS on macOS.
- Go toolchain, Rust toolchain via `rustup`, Cargo and a C linker/build dependencies required by selected crates.
- Docker + Docker Compose.
- Supabase CLI for local database/functions/migrations, and access to a separate development Supabase project.
- `curl`, `jq`, and an API client for local testing.

## 2. Suggested repo tree

```text
apps/customer_flutter/
services/api-go/
services/dispatch-rust/
supabase/
  config.toml
  migrations/
  seed.sql
api/openapi.yaml
infra/
docs/
.env.example
```

## 3. Environment configuration

Create untracked `.env` files from `.env.example`. Keep real secrets in a secret manager for staging/production.

```dotenv
APP_ENV=local
API_PORT=8080
PUBLIC_API_BASE_URL=http://10.0.2.2:8080/v1
DATABASE_URL=postgresql://<local-user>:<local-password>@<host>:5432/postgres
DATABASE_SSLMODE=disable
JWT_ISSUER=food-delivery-local
JWT_AUDIENCE=food-delivery-api
JWT_PRIVATE_KEY_FILE=./secrets/dev-jwt-private.pem
JWT_PUBLIC_KEY_FILE=./secrets/dev-jwt-public.pem
ACCESS_TOKEN_TTL=15m
REFRESH_TOKEN_TTL=720h
RUST_DISPATCH_ENABLED=true
PAYMENT_PROVIDER_MODE=sandbox
PAYMENT_WEBHOOK_SECRET=<local-placeholder>
LOG_LEVEL=debug
```

This example contains placeholders, not real credentials. `DATABASE_SSLMODE=disable` is for local development only; require TLS (`require`/verified TLS per driver and deployment) outside local. Never expose the database URL or signing key to Flutter.

## 4. Start local dependencies

1. Review `supabase/config.toml` and install the CLI per the official instructions: https://supabase.com/docs/guides/local-development/cli/getting-started
2. Start the local Supabase stack with the CLI's documented command for the installed version (commonly `supabase start`).
3. Apply migrations and seed fake data using the repository's scripts. Do not create an alternate schema manually in the dashboard without adding a migration.
4. Copy local service connection details into `.env`; verify DB connectivity with a smoke test.

Supabase connection mode depends on runtime. Persistent services can use a direct connection when the network supports it; IPv4-only deployments may need session pooling. Transaction poolers have feature limits such as prepared statement/session-state limitations. Use the official Connect page for the actual project endpoint and driver guidance: https://supabase.com/docs/guides/database/connecting-to-postgres

## 5. Run Go API

The repo may use a framework or the standard library. Example if the module entry point is `./cmd/api`:

```bash
cd services/api-go
go mod download
go test ./...
go run ./cmd/api
```

Confirm `GET /health/live` and `GET /health/ready` return the documented local responses. Readiness should fail if essential dependencies are unavailable; liveness should not cause restart loops for temporary DB outages.

## 6. Run Rust worker

```bash
cd services/dispatch-rust
cargo fetch
cargo fmt --check
cargo test
cargo run
```

The worker should not expose a public port by default. It needs a private DB/job interface and health/metrics signal appropriate for the deployment platform. Use mock dispatch jobs locally.

## 7. Run Flutter app

```bash
cd apps/customer_flutter
flutter pub get
dart format .
flutter analyze
flutter test
flutter run
```

For Android emulator to reach a host process, use the emulator host mapping (often `10.0.2.2`); physical device testing requires a reachable dev host and HTTPS/network settings appropriate to the platform. Do not disable certificate validation in shipped builds.

## 8. Verify integration

- Register test user, verify contact using local fake provider, login and inspect token expiry/refresh.
- Browse seeded restaurant and menu, create address, request quote, place COD test order.
- Replay same idempotency key; confirm the same order is returned.
- Post signed test webhook using the repo's test helper and replay it; confirm only one state transition.
- Submit as another user/role and confirm 403/404 as defined.
- Kill Rust worker and confirm jobs remain queued and are processed after restart.

## 9. Common setup errors

- **DB connection fails:** check URL copied from Supabase Connect, network/IP mode, password URL encoding, SSL requirements and max pool size.
- **Too many connections:** reduce per-process pool, reuse DB handles, use the appropriate Supabase pooler and inspect connection utilization.
- **JWT rejected:** check clock, `iss`, `aud`, key ID, signing algorithm, public-key deployment and token expiry.
- **Flutter cannot reach API:** check emulator/physical-device address, firewall, HTTPS certificate and base URL flavor.
- **Migration drift:** reset only disposable local DBs, create/review migration, and never reset a shared or production DB casually.
